```
                          │

                   （配置读写）   （设置界面，apply/collect 分离）
```

**依赖规约**（代码里实际成立，无例外）：
- `app.py` 是唯一依赖所有人的模块；其余模块**互不依赖**（除 `llm→correction_modes`、`translator→textutil`、`llm→config` 三条）
- `win32.py` 不依赖任何项目内模块，纯 ctypes 封装
- `config.py` 不依赖 GUI；`settings_ui.py` 是唯一碰 Tk 的配置相关模块
- `correction_modes.py` / `textutil.py` **纯函数、无 Tk 无网络**（可在 CI 离线断言）

## 2. 跨模块数据流

| 阶段 | 触发 | 数据流向 | 线程 |
|---|---|---|---|
| 按下热键 | `PollingHotkey`/`HookHotkey` 边沿检测 | `on_press` → `app._on_press` | hotkey 线程 |
| 录音中 | PortAudio 回调 | `_raw` 队列 → `MicCapture._run` → `on_block(pcm)` → `asr.feed` | 采集线程 + ASR 线程 |
| 识别 | 每 160 ms | WS 二进制帧 → 服务端 `partial` → `app._on_partial` → `overlay.set_text` + `translator.update` | ASR 线程 → Overlay 队列 → 主线程 |
| 松手 | 边沿 | `on_release` → `asr.end_session` → 服务端 `final` → `app._on_final` | |
| 修正 | final 到达 | `llm.correct` → `Outcome` → `injector.inject` | 修正线程 |
| 翻译 | final 到达（翻译模式） | `translator.finish()` → `TranslationResult` → 注入**译文** | 翻译线程 |
| 注入 | 文本就绪 | 剪贴板 → Ctrl+V → 延时还原 | 还原线程（daemon） |

**Tk 线程规约**：`Overlay.post()` 队列是**唯一**的跨线程通道，`root.after(30)` 在主线程消费。全项目无 Tk 对象被非主线程触碰 —— **这一条守住了**。

## 3. 已验证的真缺陷（不是猜测）

### D1 【严重】分段轮转期间音频丢失 —— 32%

**证据**：`tools/repro/repro_rotate_loss_real.py`，对**真实 WSL 服务**跑 `runtime/testdata/zh_test.wav`：

```
对照组（一次性喂完）  : 34 字
实验组（中途轮转）    : 23 字
丢失                  : 11 字（32%）
```

**根因**（三方共同作用）：
1. `client/asr.py:89-100` `rotate()` 只把 `finish` 排队，**不扣住后续音频**
2. `client/asr.py:68-79` `feed()` 在轮转期间照常把音频塞进队列
3. `wsl/r2t2_stream_server.py:308-309` 服务端收到音频时 `session is None` → **用默认参数自动开新会话**（丢掉用户的 language/context）
4. `wsl/r2t2_stream_server.py:327-328` 客户端随后发的 `start` → **丢弃旧会话** → 那段音频的文本永远进不了 final

**姊妹项目已修**：EtherealLive `client/simul.py:175-206` 实现了 `_hold_audio`/`_release_hold`，其 P6 报告记录了同样的踩坑（37.8 s 音频「丢了整整两遍」）。**这个修复没有回流到 EtherealFlow**。

**影响**：`max_utterance_sec` 默认 30 秒。**任何超过 30 秒的连续说话都会丢中间一段。**

### D2 【严重】CI 从未成功跑过一次 —— 4/4 全红

`.github/workflows/build.yml:36` 跑 `tools/run_all_tests.py`，在 GitHub Windows runner 上**第一行就崩**：
```
UnicodeEncodeError: 'charmap' codec can't encode characters ... cp1252
```
**已本地复现**（把 stdout 换成 cp1252 即崩）。失败 run：`v1.0.0` / `v0.1.0` / `v0.2.0` / `v0.3.0` 全部挂在「离线自测」这一步，打包步骤从未执行。v0.3.0 的 zip 是**手工上传**的。

连带缺陷：
- `build.yml:45` 产物自检路径 `dist\EtherealFlow\...` 是错的，实际输出在 `build/dist/`（`scripts/build_exe.py:53`）
- CI 触发条件不含 `tools/` `wsl/` `docs/` —— **改测试、改协议、改文档都不触发 CI**
- CI 不跑 5 个关键测试：`test_closed_loop.py` `test_translate_flow.py` `test_stream_client.py` `test_inject_apps.py` `test_mic_path.py`

### D3 【严重】Esc 取消是死代码 —— FR-1 静默失效

`client/hotkey.py:111` `self.active = False`，全仓**没有任何生产代码把它设成 True**（只有 `tools/test_hotkey.py:67` 设了）。
`hotkey.py:145` 和 `:267` 两个后端的 Esc 分支都要求 `self.active` → **`on_cancel` 在真实使用中永不触发**，Esc 取消本次输入这个功能根本不存在。

### D4 【中】热词从未传给识别引擎 —— 但界面和文档都声称传了

- `client/settings_ui.py:475` 界面写「会作为 context 传给识别引擎」
- `README.md:283` 写「词典热词的实际纠错（当前只作为 context 传给识别引擎）」
- `client/config.py:62` 注释写「热词既传给识别引擎当 context」
- **实际**：`client/app.py:151` 只传 `cfg["asr"]["context"]`（另一个独立字段）；`cfg["hotwords"]` 只流向 `app.py:194` → LLM

**三处文档都在说谎。** FR-7 的「热词传给识别引擎」未实现。

### D5 【中】`deep_merge` 浅拷贝 —— 会污染全局默认值

`client/config.py:68-76` `deep_merge` 返回 `dict(base)`（浅拷贝）。用户配置里**缺失**的段会直接引用 `DEFAULT_CONFIG` 的**同一个对象**：
```
merged["audio"] is DEFAULT_CONFIG["audio"] → True
```
于是 `cfg["audio"]["device"] = X` 会**改掉模块级默认值**。`load_config` 返回的就是这个被污染的 dict。已由 worker 执行验证。

### D6 【中】配置无类型校验 —— 坏配置直接崩在启动

`config.py:135-142` 只处理「JSON 解析失败」。一个合法 JSON 但类型错的配置（如 `overlay.width: "abc"`）会一路传到 `overlay.py:93` 抛 `TypeError`；`hotkey.keys: "ctrl"` 会在 `hotkey.py:79` 抛 `ValueError`，**无捕获 → 启动崩溃**。
而且损坏的配置会被**静默丢弃并用默认值覆盖** —— 用户的 API Key 和热词就没了。

### D7 【中】LLM 地址格式错误会杀掉整个修正线程

`client/llm.py:344-372` 的 `except` 覆盖 `URLError`/`OSError`/`socket.timeout`，但 `http://host:abc/v1` 抛的是 `http.client.InvalidURL` —— **既不是 URLError 也不是 OSError**，直接逃逸出 `_run` → 逃逸出 `correct` → 杀掉 `app.py:194` 的线程。**结果：不注入任何东西，`done` 状态永不设置，UI 永远停在「修正中」。**

### D8 【中】自检断言恒真 —— 4/15 行成功路径不可能失败

`tools/test_llm.py:295-298`：
```python
ok = (A and B and C and D and E) or want_changed
```
Python 优先级下等价于 `((A and B and C and D and E) or want_changed)`。凡是 `want_changed=True` 的行（ok / markdown / prefixed / quoted）**恒为真**。
`tools/test_translator.py:135` 的 `sent == "".join(dict.fromkeys([sent]))` 对**任意字符串**恒真。

### D9 【中】注入成功与否是盲的

`client/inject.py:297` `press_ctrl_v()` 的 `SendInput` 返回值被忽略，`:299` 无条件 `res.ok = True`。
- UIPI 阻止注入时（目标应用是管理员权限），**报成功但什么也没输入**
- `:294-295` 剪贴板回读不一致时只警告，**照样粘贴**（可能粘到旧内容）
- `:318` 剪贴板还原失败**完全静默**；且 `app.py:230` 在 `inject()` 返回后立刻打日志，而还原发生在 500 ms 后 → **日志里永远看不到「剪贴板已还原」**
- `inject.py:149-150` 的 `has_other` 不含 `CF_BITMAP`/`CF_DIB`/`CF_DIBV5` → **纯图片剪贴板会被 `EmptyClipboard` 静默销毁**

### D10 【中】翻译方向逐段判断 —— 一句话会被劈成两种语言

`client/translator.py:222-224` 每段独立调 `guess_target_language`（数 CJK vs 拉丁字符）。一句话里中英混说时，**前半段译成英文、后半段译成中文**。

### D11 【中】翻译失败会静默吞掉整句

`client/translator.py:228-237` 某段翻译失败 → 该段**不追加**，但 `degraded` 仍为 False（`:138` 运算符优先级让 `failed>0` 失效）→ **注入的文本悄悄少了那句话**，用户和日志都看不出来。

### D12 【轻】麦克风尾块必丢 / 音量波形没接线

- `client/audio.py:170` `MicCapture.flush()` **无调用者** → 每次松手丢掉最多 160 ms 尾音
- `client/audio.py:96` `peak` 算了但**没人读** → FR-3 的音量波形没有
- `client/settings_ui.py:23` `list_input_devices` **导入了但没用** → FR-2「设置里列出输入设备」没有，麦克风只能靠命令行 `--device`

### D13 【轻】设置界面改完必须重启才生效

`client/app.py:93` LLM 客户端在 App 初始化时构造一次 → 改修正模式 / 改 Prompt 都要重启。界面虽然提示了「重启后生效」，但 `llm.max_tokens` / `audio.device` / `asr.max_utterance_sec` 等**根本没在界面上**，只能手改 JSON。

### D14 【轻】服务暴露到局域网

`wsl/r2t2_stream_server.py:75` `HOST = "0.0.0.0"` —— **无鉴权**的识别服务在局域网内可访问。

### 4.4 对标项目的能力缺口

EtherealFlow **领先**的地方：增量流式翻译（push-2-talk / VoiceX / typeflux 都没有）、append-only 真流式后端、WS_EX_NOACTIVATE 加在**顶层窗口**（正是 typeflux 文档警告的坑）、粘贴前回读校验。

EtherealFlow **缺**的（对标项目有）：
- 拼音/音素热词强制纠错（CapsWriter）
- TNL 确定性规范化层（push-2-talk）
- 按目标应用区分注入方式（VoiceX）
- VAD 静音过滤（Handy）
- 多 ASR 引擎（Whispering/Handy）
- 注入结果三态（typeflux：delivered/unconfirmed/notApplied）
- Prompt 长度上限 + 分段优先级排序（OpenTypeless/OpenWhispr）
