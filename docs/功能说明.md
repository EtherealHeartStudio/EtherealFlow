# EtherealFlow · 缥缈心流 —— 功能说明

> 这份文档回答一个问题：**这个软件到底能干什么？**
> 不谈架构、不谈代码，只讲你按下按钮之后会发生什么。
>
> 最后更新：2026-10-25 ｜ 配套：`docs/开发需求文档-v2.0.md`（工程侧）、`docs/开发计划-v2.0.md`（排期侧）

---

## 一句话

**按住 `Ctrl + Win` 说话，屏幕上实时看着字长出来；松开手，干净的文字直接落进你正在打字的那个输入框。**

语音和文字**全程不离开你的电脑** —— 识别模型跑在本机 WSL 里，修正用的模型也可以跑在本机。

## 一、实际用起来是什么样

```
  你正在 Word 里写东西，光标停在段落中间
                ↓
  按住 Ctrl + Win，开始说话
                ↓
  ┌────────────────────────────────────────────────┐
  │  🎙 正在听…                              00:08  │
  │                                                 │
  │  舰长，升级 https 之后，再次测试               │  ← 字一个一个长出来
  │  微软语音服务，这是一段中文语音测试              │
  └────────────────────────────────────────────────┘
  ↑ 这个悬浮窗不抢焦点，你可以在 Word 里继续敲字
                ↓
  松开 Ctrl + Win
                ↓
  ⏳ 修正中…（约 1–3 秒，取决于你配的模型）
                ↓
  ✅ 完成 —— 修正后的文字已经进了 Word 的光标处
```

## 二、功能清单

### 2.1 核心链路（这些是产品的全部价值）

| # | 功能 | 你能感知到什么 |
|---|---|---|
| F1 | **按住说话** | 按住 `Ctrl + Win` 开始，松开结束。默认键可改 |
| F2 | **实时出字** | 边说边出字，不是说完才显示。第一个字约 0.8 秒后出现 |
| F3 | **不抢焦点的悬浮窗** | 悬浮窗出现时，**你原来那个窗口的焦点不变**，可以继续敲字、继续选中文字 |
| F4 | **AI 修正** | 松手后自动整理：去口水词、补标点、改同音错别字、数字用阿拉伯数字 |
| F5 | **直接注入** | 整理好的文字**直接落进你正在打字的输入框**，不用复制粘贴 |
| F6 | **流式翻译**（可选） | 开启后原文在上、译文在下同时滚动；**最终提交的是译文** |
| F7 | **三种修正力度** | 同一句话，可以选「一个字都不动」/「轻度清理」/「整理成书面语」 |

### 2.2 让它「不掉链子」的那些功能

| # | 功能 | 你能感知到什么 |
|---|---|---|
| F8 | **长语音自动分段** | 说超过 30 秒不会变卡，程序自动切段，对你无感 |
| F9 | **断线自动重连** | 识别服务崩了，客户端自己重连；服务恢复后自动接上（连语言设置和热词都还在） |
| F10 | **剪贴板保护** | 注入完把你原来的剪贴板**还原**。剪贴板里是图片时改用逐字键入，不破坏它 |
| F11 | **注入方式可切** | 剪贴板 Ctrl+V（兼容性好）/ 逐字键入（给不让粘贴的应用） |
| F12 | **识别服务自启** | WSL 里的识别服务配成 systemd 服务，开机自启、崩溃自动拉起（约 13 秒恢复） |

### 2.3 设置界面（6 个分组，一个不多）

打开方式：`python -m client.app --settings`

| 分组 | 能配什么 |
|---|---|
| **热键** | 录音快捷键、触发方式（轮询 / 低级钩子） |
| **识别** | 服务地址、语言（自动/中/英）、识别上下文 |
| **修正** | 开关、**三张卡片选力度**、自定义模式、Prompt 覆盖、模型地址与 Key、超时 |
| **翻译** | 开关、目标语言、触发阈值（静默秒数 / 字数） |
| **注入** | 注入方式、是否还原剪贴板 |
| **词典** | 热词表（每行一个） |

**自定义修正模式**：内置三种之外，你可以自己起名、写说明、写 Prompt，
界面上跟内置模式**同等对待**（卡片式选择，带效果示例）。

### 2.4 三种修正力度的实际差别（实测输出）

同一句原始识别结果 `嗯我跟你说明天回议吧不对不对先讨论排期再聊产品方案`：

| 模式 | 结果 | 耗时 |
|---|---|---|
| **不整理** | 嗯我跟你说明天**会议**吧不对不对先讨论排期再聊产品方案 | 3.7 s |
| **轻度整理** | 我跟你说，**明天会议**吧，先讨论排期，再聊产品方案。 | 2.2 s |
| **深度整理** | 明天会议讨论：**1. 排期；2. 产品方案。** | 2.2 s |

> 「不整理」只改**明显识别错的字**（回议→会议），其他一字不动。
> 「轻度整理」去掉口水词和自我修正，补上标点，保留你的措辞。
> 「深度整理」保留原意，整理成书面表达。

### 2.5 模型接入：随便你接什么

- **任意 OpenAI 兼容接口**：本机 Ollama / LM Studio / llama.cpp server / vLLM，或者云端 API
- 设置界面里有**预设**、**模型列表下拉**、**连接自检按钮**
- **两个翻译引擎可选**（v1.0 计划中）：
  - 引擎 A：通用 LLM（已接好，零额外资源）
  - 引擎 B：Confucius4-T3PO 专训同传模型（本机跑，9.8 GB 权重，纯 CPU 不占显存，翻译质量更好）

## 三、实测性能（本机 RTX 4070 Laptop 8GB / WSL2）

| 项 | 实测 | 来源 |
|---|---|---|
| 模型加载 | 4.3 s（服务常驻，客户端连上就能用） | README 实测 |
| 第一个字出现 | **0.80 s** | 2026-10-25 重测 |
| 6.7 秒语音的流式解码 | 0.56× 实时（比说话快一倍） | README 实测 |
| 33.7 秒语音 | 0.88× 实时 | README 实测 |
| 53.9 秒语音 | 1.15× 实时（跟不上）→ 所以客户端 30 秒自动分段 | README 实测 |
| 分段后（同一份 33.7 秒音频） | **0.54× 实时** | README 实测 |
| Windows ↔ WSL 握手 | 17 ms | README 实测 |
| 打包体积 | **25 MB**（zip，自带 Python，免安装） | 2026-10-25 实测 |

> 首字延迟 README 里记的是 1.20 s，是旧数据；2026-10-25 重测是 **0.80 s**
> （复现命令：`tools/test_stream_client.py`）。S5 阶段会把这套测量脚本化并重测一遍。

**修正/翻译延迟**取决于你接的模型：
本机非推理模型约 1–2 s；云端推理模型可能 6–30 s。

## 六、一分钟上手

```bash
# 1. 启动 WSL 里的识别服务（已配成开机自启，通常不用管）
wsl -d Ubuntu -u r2t2 -- bash -lc 'export XDG_RUNTIME_DIR=/run/user/1005; systemctl --user status r2t2-stream'

# 2. 跑客户端
cd EtherealFlow
.venv/Scripts/python.exe -m client.app

# 3. 在任意输入框里，按住 Ctrl + Win 说话，松开
```

**第一次用没反应？** 多半是麦克风选错了（很多机器默认录音设备是虚拟声卡）：

```bash
.venv/Scripts/python.exe -m client.app --list-devices   # 看有哪些设备
```

**想开翻译/改设置**：

```bash
.venv/Scripts/python.exe -m client.app --settings
```

**想先试一遍不碰麦克风**（用现成音频跑完整链路）：

```bash
.venv/Scripts/python.exe -m client.app --replay ../runtime/testdata/zh_test.wav --exit-after-final --inject-mode none
```
